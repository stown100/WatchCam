# WatchCam

Видео камерой iPhone + звук с микрофона Apple Watch, автоматическая синхронизация по звуку и сохранение в Фото.

## Структура

```
project.yml            описание проекта для XcodeGen (сам .xcodeproj не хранится в репозитории)
Config/                Base.xcconfig + ваш Local.xcconfig (Team ID, префикс bundle ID)
Shared/                протокол WatchConnectivity и общие типы (компилируется в оба приложения)
SyncKit/               Swift-пакет без UI: NTP-оценка часов, GCC-PHAT кросс-корреляция,
                       дрейф, декодирование, пересэмплирование, выровненный WAV + тесты
iOS/                   приложение iPhone
  Camera/              AVCaptureSession, зум, фокус/экспозиция, превью для часов
  Connectivity/        PhoneLink — сторона WatchConnectivity на iPhone
  Recording/           RecordingCoordinator — старт/стоп обоих устройств, статусы
  Processing/          SessionProcessor (sync → композиция → экспорт), MovieComposer, Фото
  Storage/             сессии в JSON: Application Support/Sessions/<id>/session.json
  UI/                  экраны: камера, просмотр, библиотека, настройки
Watch/                 приложение часов
  Audio/               AudioRecorder (AVAudioEngine → CAF, заполнение пропусков тишиной)
  Connectivity/        WatchLink, очередь неотправленных файлов
  App/, UI/            модель и экраны
```

## Как устроена синхронизация

1. **Грубо.** Часы запоминают время первого сэмпла по своим монотонным часам (`mach_absolute_time`), iPhone — время первого кадра (на iOS 18.2+ точный `startPTS`, раньше — момент колбэка). Каждые 0.25–1 с часы шлют heartbeat, он же NTP-пинг (4 метки времени). Из лучших 40 замеров берётся замер с минимальным round-trip. Если пинги не прошли, используется системное время устройств.
2. **Точно.** Звук iPhone из видео и звук часов декодируются в моно 8 кГц через AVAssetReader (тот же таймлайн, что у AVComposition, поэтому задержка AAC-энкодера учитывается одинаково). До трёх окон по 20 с (начало/середина/конец, выбираются по «насыщенности» звука), GCC-PHAT корреляция через vDSP FFT в окне ±2 с, параболическая интерполяция пика.
3. **Уверенность.** z-оценка пика над фоном, отношение к второму пику, плюс проверка: две половинки окна должны независимо дать то же смещение (±3 мс). Если ни одно окно не прошло — «синхронизация приблизительная», ролик не сохраняется автоматически.
4. **Дрейф.** Через окна проводится прямая `смещение(t)`. Если за всю запись расхождение больше одного кадра, звук часов пересэмплируется (AVAudioConverter, качество Mastering).

Результаты тестов на синтетике: ошибка < 0.5 мс; дальний микрофон с реверберацией находится вплоть до SNR −25 дБ; несвязанные записи отбраковываются.

## Формат звука на часах

**Во время записи звук всегда пишется без сжатия (PCM 16 бит в CAF).** Причина: если приложение на часах завершится посреди записи, сжатый файл не прочитать. Проверено на Mac: после убийства процесса AAC в CAF открывается с длиной 0 секунд, а PCM в CAF читается целиком всеми способами, которыми его потом открывает iPhone. Заодно это почти не нагружает процессор, что важно для работы в фоне.

После чистой остановки файл превращается в тот формат, что выбран в настройках, и уходит на iPhone:

По умолчанию **AAC (VBR, максимальное качество)**:
- узкое место — сам микрофон часов, а не кодек: AAC на максимальном качестве на слух неотличим от исходника;
- файл в 4–6 раз меньше PCM — 10 минут ≈ 10 МБ против ≈ 58 МБ. По Bluetooth это минута ожидания против нескольких.

**PCM 16 бит** — опция для тех, кто будет серьёзно обрабатывать звук. 16 бит с запасом перекрывают динамический диапазон микрофона часов. Восстановленная после обрыва запись тоже передаётся как PCM.
Частоту дискретизации watchOS выбрать не даёт: пишем ту, что отдаёт микрофон. Она видна на экране просмотра записи («Звук часов: AAC, 48000 Гц») и в логах.

## Где что делать

| Где | Что там делается |
|---|---|
| **Mac, Терминал** (или терминал VS Code) | все команды из этого файла: `xcodegen`, `swift test`, `xcodebuild`, `cp`, `grep`. Сначала перейдите в папку проекта: `cd ~/"Pet Projects"/WatchCam` |
| **Mac, Xcode** | вход в Apple ID, выбор команды подписи, кнопка ▶︎ Run: она собирает приложение и ставит его на iPhone по кабелю |
| **iPhone** | только переключатели в Настройках (режим разработчика, доверие разработчику) и само приложение |
| **Apple Watch** | только переключатель режима разработчика в Настройках и само приложение |

На iPhone и часах **никаких команд вводить не нужно**: терминала там нет. Mac нужен для установки и переустановки раз в 7 дней. Снимать можно без него.

## Сборка и тесты (для разработки, для установки не нужны)

Всё ниже — **на Mac, в Терминале**, из папки проекта. Чтобы просто поставить приложение на телефон, достаточно шагов из раздела «Установка».

```bash
cd ~/"Pet Projects"/WatchCam

# пересоздать WatchCam.xcodeproj (после изменения project.yml или добавления новых .swift-файлов)
xcodegen generate
open WatchCam.xcodeproj

# тесты синхронизации, прямо на Mac (~10–30 с)
swift test --package-path SyncKit

# те же тесты в симуляторе iPhone (симулятор запустится сам, ~3 мин)
xcodebuild -project WatchCam.xcodeproj -scheme WatchCam \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test

# проверка, что всё компилируется под настоящие устройства (без подписи)
xcodebuild -project WatchCam.xcodeproj -scheme WatchCam -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
xcodebuild -project WatchCam.xcodeproj -scheme WatchCamWatch -destination 'generic/platform=watchOS' CODE_SIGNING_ALLOWED=NO build
```

## Установка на устройства с бесплатным Apple ID

В квадратных скобках указано, где выполнять шаг.

1. **[Mac, Xcode]** Xcode → Settings → Accounts → «+» → Apple ID. Появится команда «Ваше Имя (Personal Team)».
2. **[Mac, Терминал]** Создайте личный конфиг и сгенерируйте проект:
   ```bash
   cd ~/"Pet Projects"/WatchCam
   cp Config/Local.xcconfig.example Config/Local.xcconfig
   xcodegen generate
   open WatchCam.xcodeproj
   ```
3. **[Mac, Xcode]** Слева нажмите на проект WatchCam → таргет **WatchCam** → вкладка Signing & Capabilities → Team → ваша Personal Team.
4. **[Mac, Терминал]** Узнайте Team ID, который Xcode только что записал в проект:
   ```bash
   grep -m1 DEVELOPMENT_TEAM WatchCam.xcodeproj/project.pbxproj
   ```
   Откройте `Config/Local.xcconfig` в VS Code и впишите это значение: `DEVELOPMENT_TEAM = XXXXXXXXXX`. Затем снова выполните `xcodegen generate`. Теперь команда подписи не потеряется при пересоздании проекта, и подхватится обоими приложениями.
   `BUNDLE_ID_PREFIX` в том же файле должен быть уникальным во всём мире. Если Xcode пишет «Failed to register bundle identifier», поменяйте его, например на `com.serhiiborodulin.wc2026`, и снова выполните `xcodegen generate`.
5. **Режим разработчика на iPhone.**
   - **[iPhone]** Подключите iPhone к Mac кабелем и нажмите «Доверять этому компьютеру».
   - **[Mac, Xcode]** В центре верхней панели есть плашка вида «WatchCam › iPhone 18 Pro»: слева схема (что запускать), справа устройство (где запускать). Нажмите на название устройства и в разделе **iOS Devices** (верх списка) выберите свой настоящий iPhone. Пункты из «iOS Simulators» — виртуальные телефоны на Mac, без камеры: для съёмки они не подходят. Если вашего iPhone в списке нет, проверьте, что он подключён кабелем, разблокирован и на нём нажато «Доверять».
   - **[iPhone]** Настройки → Конфиденциальность и безопасность → Режим разработчика → Вкл. → перезагрузка → «Включить». Этот пункт появляется только после того, как Xcode увидел iPhone.
6. **Режим разработчика на часах.** Режим разработчика на iPhone уже должен быть включён.
   - **Bluetooth включён на всех трёх устройствах, включая Mac.** Без Bluetooth на Mac Xcode часы не находит. Mac, iPhone и часы — в одной Wi-Fi-сети, VPN на Mac выключен.
   - **[Часы]** Наденьте, разблокируйте, держите экран включённым.
   - **[Mac]** Выньте и снова вставьте кабель iPhone. В момент подключения iPhone Mac сам сопрягается с часами через него. Если часы в этот момент заблокированы, попытка молча проваливается. Тогда просто переподключите кабель ещё раз, с разблокированными часами. Вопроса «Доверять?» на часах может и не быть.
   - **[Mac, Xcode]** Откройте окно устройств: **⇧⌘2**, или в строке меню **Product → Destination → Manage Devices…**, или нажмите на название устройства в верхней плашке и выберите **Manage Devices…** внизу списка. В Xcode 27 этого окна больше нет в меню Window; в старых версиях оно называлось Window → Devices and Simulators. Часы появятся отдельной строкой, например «Apple Watch — Сергей». Симуляторы в этом же списке подписаны «Simulator», «Apple Watch Series 12 … Simulator» — это не ваши часы.
   - **[Часы]** Настройки → Конфиденциальность и безопасность → в самом низу **Режим разработчика** → Вкл. → перезагрузка → «Включить». Пункт появляется только после того, как Mac сопрягся с часами.
   - Надпись «Screen Sharing Unavailable … must be running iOS 27.0» при выборе iPhone — не ошибка. Это функция показа экрана iPhone на Mac, для установки приложения она не нужна. Подробности об устройстве открываются кнопкой **«i»** в правом верхнем углу окна.
   - **Проверка из Терминала, [Mac, Терминал]:** `xcrun devicectl list devices`. Часы должны быть в списке с пометкой `physical` в колонке Reality.
   - **Как Mac работает с часами:** управляющий канал идёт **по Bluetooth** (поэтому Bluetooth на Mac обязателен), а данные — через туннель **по Wi-Fi**. Рядом с iPhone часы держат связь по Bluetooth и Wi-Fi почти не используют, поэтому туннель может не подняться (в журнале `Timed out`). Тогда: **[iPhone]** Настройки → Bluetooth → временно выключить; **[Часы]** Настройки → Wi-Fi → нажать на домашнюю сеть. После установки приложения включите Bluetooth на iPhone обратно.
   - **Если часы не появляются:**
     1. Bluetooth на Mac включён. Это была главная причина при первой настройке.
     2. Переподключите кабель iPhone, когда часы точно разблокированы и экран горит.
     3. Перезагрузите все три устройства. После перезагрузки сначала разблокируйте часы и только потом подключайте iPhone.
     4. **Не используйте** на iPhone «Для разработчиков → Очистить доверенные компьютеры»: после этого Xcode не всегда сопрягается с iPhone заново сам. Если уже очистили, **[Mac, Терминал]** выполните `xcrun devicectl manage pair --device <UDID iPhone>` (UDID есть в выводе `xcrun devicectl list devices`) и нажмите «Доверять» на iPhone.
7. **[Mac, Xcode]** Схема **WatchCam**, устройство — ваш iPhone → ▶︎ (Cmd+R). Xcode соберёт приложение и установит его на iPhone.
   - **[Mac]** При первой сборке появится «codesign хочет получить доступ к ключу… в связке ключей». Введите **пароль от учётной записи Mac** (которым входите в систему) и нажмите **«Разрешать всегда»**, иначе окно будет появляться для каждой части приложения и при каждой сборке.
8. **[iPhone]** При первом запуске iPhone скажет «Ненадёжный разработчик». Настройки → Основные → VPN и управление устройством → «Developer App» с вашим Apple ID → «Доверять». Потом откройте WatchCam с домашнего экрана.
9. **Приложение на часах.** Оно лежит внутри iOS-приложения и иногда ставится само. Если не появилось:
   - **[iPhone]** приложение «Watch» → «Мои часы» → внизу «Доступные программы» → WatchCam → «Установить». Если там ошибка «This app could not be installed at this time», ставьте с Mac одним из способов ниже;
   - **[Mac, Xcode]** схема **WatchCamWatch**, устройство — часы → ▶︎. Так ещё и видны логи с часов;
   - или **[Mac, Терминал]** (сначала соберите проект через ▶︎ на iPhone):
     ```bash
     xcrun devicectl list devices    # UDID часов — в колонке Identifier
     xcrun devicectl device install app --device <UDID часов> \
       ~/Library/Developer/Xcode/DerivedData/WatchCam-*/Build/Products/Debug-iphoneos/WatchCam.app/Watch/WatchCamWatch.app
     ```
   - Оба способа с Mac требуют туннеля к часам. Если Xcode пишет, что не может подключиться, используйте приём с Bluetooth из шага 6. После установки **включите Bluetooth на iPhone обратно**: через него общаются приложения на iPhone и часах.
10. **Готово.** Дальше Mac не нужен: открывайте WatchCam на iPhone и на часах как обычные приложения.
11. **Каждые 7 дней** бесплатный профиль истекает, и приложения перестают открываться. **[Mac, Xcode]** Подключите iPhone и снова нажмите ▶︎: данные приложения (записи) сохранятся. **Не удаляйте приложение** с iPhone: вместе с ним удалятся записи, которые ещё не сохранены в Фото.
    Лимит: не больше 3 приложений с бесплатной подписью на устройстве. WatchCam занимает одно место на iPhone и одно на часах.

Полезно, **[Часы]**: Настройки → Основные → Возврат к циферблату → WatchCam → «Вернуться в программу». Тогда после опускания руки часы вернутся в WatchCam, а не на циферблат.

**Логи, [Mac]:** Console.app → слева выберите iPhone или часы → в поиске `subsystem:WatchCam`. На часах видна реальная частота микрофона («Audio session sample rate…»), на iPhone — результат синхронизации по каждому окну.

**Дневник часов, [Mac, Терминал]:** приложение на часах ведёт короткий дневник прямо на диске, он переживает завершение приложения. Каждые 5 секунд записи там строка `alive`, и дыра между такими строками значит, что приложение в это время не работало.
```bash
xcrun devicectl device copy from --device <UDID часов> --user mobile \
  --domain-type appDataContainer --domain-identifier <BUNDLE_ID_PREFIX>.watchcam.watchkitapp \
  --source Documents/Journal/journal.log --destination journal.log
```

## Если часы не на руке (лежат на столе, рядом)

**Проверено на реальных часах (Series 8, watchOS 26.6), но пока на одном коротком дубле.** Запись начата при открытом приложении, часы сразу сняты, через ~15 с заблокировались, дубль 1,5 минуты. Звук писался всё время, в том числе на заблокированных часах, и дошёл до iPhone; синхронизация по звуку 98%. Длинный дубль (10+ минут) на снятых часах ещё не проверялся.

До исправления, в единственной реальной попытке (часы сняты и заблокированы, дубль 9:40), приложение на часах завершилось во время записи, а при следующем запуске удалило незаконченный файл, и звук потерялся.

Что видно на iPhone, пока часы сняты:
- **Значок часов во время записи.** Пока WatchCam на экране часов, там «Пишут звук» и полоска уровня. Когда приложение уходит с экрана, watchOS закрывает быстрый канал связи, и вместо этого часы раз в несколько секунд присылают короткую сводку. Тогда значок показывает «Пишут в фоне», а если сводка не приходит — жёлтое «Часы в фоне». Само по себе это не ошибка. Оранжевое «Часы не пишут звук» — уже проблема.
- **«Ждём звук» после остановки.** Файл готов сразу, но в проверке он пришёл только через 29 секунд после того, как приложение на часах снова оказалось на экране, а до этого ждал 1,5 минуты. Похоже, watchOS не отправляет файл с заблокированных часов. Это одно наблюдение, но совет простой: откройте WatchCam на часах, и файл придёт.

Что сделано, чтобы этого не повторилось:

- **Приложение держится запущенным.** На время записи оно открывает сессию `WKExtendedRuntimeSession` типа «физиотерапия», единственный тип без отдельных разрешений, который работает в фоне. Лимит этой сессии — 1 час, дальше watchOS может приостановить приложение. Название типа не имеет отношения к делу: для приложения из App Store такое использование не подошло бы, для личного оно безвредно.
- **Звук не теряется, даже если приложение всё-таки завершится.** Файл читается до места обрыва, а данные для синхронизации сохраняются каждые 5 секунд. Откройте WatchCam на часах: при запуске приложение само восстановит запись и отправит её на iPhone.
- **Видео не обрезается.** Если часы записали только часть, ролик остаётся полной длины, а недостающие куски берутся со звука iPhone. На экране просмотра написано, сколько именно.
- **Видно сразу.** Если часы перестали писать звук или отвечать, значок на экране камеры iPhone станет оранжевым прямо во время съёмки.

Чего исправить нельзя: **watchOS не даёт запустить микрофон заново в фоне**, только на экране ([ответ инженера Apple](https://developer.apple.com/forums/thread/750432)). Если запись прервётся, например звонком или Siri, звук вернётся, только когда вы откроете приложение на часах. Этот кусок заполнится звуком iPhone.

Оговорки:

- **Блокировка.** Если включено «Распознавание запястья» (оно включено по умолчанию, когда на часах есть код-пароль), снятые часы блокируются. Чтобы нажать «Старт» на часах, или чтобы iPhone мог запустить запись (для этого приложение на часах должно быть открыто на экране), часы придётся разблокировать кодом.
- **Экран гаснет — это нормально.** Запись продолжается в фоне, как с опущенной рукой. Остановить проще с iPhone. На часах достаточно коснуться экрана, но если они успели заблокироваться, сначала придётся ввести код.
- На время съёмки можно выключить распознавание запястья: **[Часы]** Настройки → Код-пароль → Распознавание запястья (или **[iPhone]** приложение «Watch» → Код-пароль). Тогда часы не блокируются при снятии. Минус: часть функций здоровья не работает, пока это выключено, так что после съёмки включите обратно.
- **Звук.** Выигрыш от часов в том, что микрофон близко ко рту. Часы на столе в полуметре от вас всё равно лучше iPhone в трёх метрах, но хуже, чем на руке. Зато нет шорохов от рукава и жестов. Стол передаёт стуки и вибрации, поэтому подложите что-нибудь мягкое (салфетку, чехол).

Как проверить: положите часы на стол, начните запись, подождите 2–3 минуты, пока экран погаснет и часы заблокируются, и всё это время говорите. Потом проверьте ролик и строки «Часы записали не всё» и «Запись на часах прерывалась» на экране записи. Что происходило на самом деле, покажет дневник часов (см. выше).

## Чек-лист на устройствах

### Фаза 1 — основной сценарий
- [ ] Первый запуск iPhone: запросы камеры и микрофона; превью на весь экран.
- [ ] Кнопки 0.5 / 1 / 2 / 3: объективы переключаются плавно, pinch-зум работает, есть переключение на фронтальную камеру.
- [ ] Часы: запрос микрофона; статус «iPhone готов». На iPhone значок часов «Готовы».
- [ ] **Старт с часов:** вибрация, iPhone начинает запись (красный таймер), значок «Пишут звук», полоска уровня на iPhone реагирует на голос.
- [ ] **Фоновая запись:** во время записи опустите руку на 1–2 минуты и продолжайте говорить. Поднимите руку: таймер идёт, вверху часов оранжевый значок микрофона. В итоговом ролике голос непрерывен, а на экране просмотра нет строки «Запись на часах прерывалась».
- [ ] **Стоп с часов** → iPhone останавливается → «Звук с часов: N%» → «Синхронизировано» → ролик в Фото.
- [ ] **Старт с iPhone** при открытом приложении на часах: часы стартуют. При закрытом: iPhone просит открыть WatchCam на часах и предлагает «Записать только с iPhone».
- [ ] **Стоп с iPhone при опущенной руке:** часы останавливаются в течение 1–2 с (проверьте, подняв руку).
- [ ] **Часы на столе:** запись 2–3 минуты, пока часы сняты и заблокированы (см. раздел «Если часы не на руке»).
- [ ] **Точность:** хлопните в ладоши в кадре в начале и в конце дубля. В Фото покадрово: звук хлопка совпадает с кадром, где ладони сомкнулись.
- [ ] Поверните iPhone горизонтально **до** записи: ролик в Фото горизонтальный.
- [ ] Во время записи свайпните домой или примите звонок: запись корректно закончилась, файл открывается, часы тоже остановились.
- [ ] Экран iPhone не гаснет, пока открыт WatchCam.

### Фаза 2
- [ ] Тап по экрану — квадрат фокуса и ползунок экспокоррекции. Долгое нажатие — «Фокус и экспозиция заблокированы».
- [ ] Настройки: 1080p/60, H.264, HDR, стабилизация «Выключена». Строка «Сейчас: …» меняется. HDR-ролик в Фото с пометкой HDR.
- [ ] Библиотека: статусы «Записывается → Ждём звук с часов → Синхронизировано → Сохранено», удаление свайпом.
- [ ] Ручной сдвиг звука: в превью сдвиг на ±100 мс заметен на слух. «Сохранить в Фото ещё раз» сохраняет исправленную версию.
- [ ] **Дрейф:** запись 15–20 мин с хлопками в начале и конце. На экране просмотра «дрейф часов N ppm», оба хлопка в синхроне.
- [ ] **Исходники в «Файлы»:** видео и `_watch.wav`. В DaVinci Resolve или Final Cut оба файла на 00:00 таймлайна совпадают.
- [ ] **Приблизительная синхронизация:** закройте микрофон iPhone пальцем или отойдите очень далеко. Должно появиться предупреждение, ролик не сохраняется автоматически.
- [ ] **Звук пришёл позже:** остановите запись и сразу закройте WatchCam на iPhone. Откройте позже: запись сама синхронизируется. Ещё вариант: уйдите с часами из зоны Bluetooth, остановите запись, вернитесь.

### Фаза 3
- [ ] Колёсико Digital Crown на часах плавно зумит камеру iPhone, на часах виден бейдж «2.0×». Зум останавливается на шагах 0.5 / 1 / 2 / 3 / 5 / 8: даже быстрый поворот заканчивается на ближайшем шаге, а чтобы пройти его, нужно докрутить дальше. Без записи на шаге лёгкий щелчок, во время записи колёсико работает без вибрации, чтобы щелчки не попадали в звук. На iPhone 15 Pro ×0.5, ×1, ×2 и ×3 идут без цифрового увеличения, а ×5 и ×8 цифровые: объектива длиннее ×3 там нет.
- [ ] Свайп влево на часах — кадр с iPhone обновляется так часто, как позволяет связь (не чаще 8 раз в секунду), ориентация верная и при горизонтальном iPhone. Реальные цифры видны в консоли Xcode при запуске на iPhone, каждые 5 секунд: `Watch preview: … fps, … KB/frame, round trip … ms`.
- [ ] В 4K/60 HDR превью может отключиться (лимит пропускной способности камеры): это нормально, запись важнее.
- [ ] С опущенной рукой (Always-On) на часах упрощённый экран.
- [ ] При перегреве на iPhone появляется предупреждение.

## Известные ограничения
- Камера iOS работает только на экране: при уходе в фон запись корректно завершается, но продолжить её нельзя.
- Если свернуть приложение во время синхронизации или сохранения, iOS даёт примерно 30 секунд, чтобы закончить. Не успело — работа продолжится сама, когда вы вернётесь в приложение.
- Начать запись с микрофона часов можно, только когда приложение на часах открыто (ограничение watchOS). Продолжать запись в фоне можно, а вот возобновить после прерывания — только на экране.
- Синхронизация выравнивает звук часов по звуку, который слышал iPhone. Если iPhone в 3 м, звук будет «как слышно с 3 м» (+9 мс) — это незаметно для глаза. При желании подстройте вручную.
